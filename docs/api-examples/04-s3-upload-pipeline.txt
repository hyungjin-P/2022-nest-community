# 04 S3 업로드·삭제 파이프라인과 초안 재작성 정리 — POST·DELETE /file, POST /feed/createFeed (stage1 8절 근거 5·4)
# 업로드: 버킷 도메인 화이트리스트(file.service.ts:40-45) → 경로 정규식(:48-54) → uuid 키(:61-65) → S3 업로드 후 file·file_tag 저장(:73-111) → tag 별 분기 저장(:113-138, feed → feed_picture).
# 삭제: S3 객체 삭제 → 도메인 행·file_tag·file 정리(:145-184). rewrite=true 면 이전 초안의 S3 파일·태그·행을 함께 정리한다(feed.service.ts:447-463).
# 목업: S3 는 FakeS3(src/_mock/fakes/aws.ts)가 .mock/uploads/<버킷>/<키> 에 저장한다. 응답의 location·etag 는 FakeS3 값이고, url 은 원본 코드가 만드는 문자열(https://<버킷 도메인>/<키>)이다 — 그 도메인으로 요청하지 않는다.
# 업로드 파일은 fixture SVG 일러스트(src/_mock/assets/img/feed/feed-07.svg·feed-08.svg)다.
# 한계(stage1 9절 4): feed 분기만 await 가 없다(:115) → 업로드 응답 뒤 300ms 기다려 확인했다. 업로드 후 DB 저장 실패 시 보상 처리가 없다. 검증 실패는 500 이다.
